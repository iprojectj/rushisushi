---
name: Fresh backend recovery
description: Why the Rūshī backend uses a fresh database rather than recovered Lovable data.
---

The user lost access to Lovable and had only the public GitHub export. They explicitly approved rebuilding the backend with a new database on Replit.

**Why:** the old backend and its private credentials were unavailable.

**How to apply:** do not claim historical customers, orders, or settings were recovered. Treat the approved fresh database as intentional, and distinguish restored application functionality from historical data recovery.
